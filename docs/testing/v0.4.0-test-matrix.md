## How to read this matrix

Each v0.4.0 feature gets a **section**. Inside each section:

1. **Parity-surface table** — one row per applicable surface from the 11-row parity
   checklist (`.github/instructions/parity.instructions.md` §1). Status legend:
   - ✅ **Covered** — tests exist today and assert the behavior.
   - 🟡 **Partial** — some assertions exist; named gaps remain.
   - ❌ **Missing** — no coverage yet (feature not merged, or coverage never written).
   - **N/A** — surface does not apply to this feature (with reason).
2. **Acceptance-criteria cases** — the positive-path tests that prove the feature works.
3. **Edge cases** — nullable fields, bounds, placeholders, search/display exclusion, SSRF, CSV.
4. **GAPS** — coverage that must be added before the feature can merge cleanly.

A final **Cross-Cutting Invariants** section captures tests that must hold regardless of feature.

## Cross-Cutting Invariants *(feature-independent — assert for every new field)*

### INV-1 · Placeholder symmetry
Placeholder meals (`placeholderKind` set, e.g. "Free Day"/"Leftovers") must be inert to metadata:
- **Un-editable:** service throws "Cannot modify placeholder meal"; **both** `PUT` and `PATCH` → 403 on REST **and** agent.
- **Un-creatable via agent** `create_meal`.
- **Excluded from search/list** on **both** REST and agent surfaces.
- Any new v0.4.0 field must be **un-settable** on placeholders on **both** surfaces.
- Asymmetry (settable on one surface, blocked on the other) = **parity violation → fail**.

### INV-2 · Display deny-by-default
`DisplayMealEntry` exposes **exactly 6 fields**: `id`, `name`, `description`, `placeholderKind`, `icon`, `imageUrl`.
- Every **new** v0.4.0 field (favorite, rating, instructions, tags, categories, prep/cook/servings, sourceUrl, notes, lastCookedOn) requires an **explicit negative test**: field is **NOT** present in the display/api-key response.
- **Exception:** `imageUrl` (#103) **is** in the 6 → **positive** test it IS exposed.
- Adding a field to display is a deliberate act requiring a test flip; the default is not-leaked.

### INV-3 · Auth across 3 surfaces
| Surface | Chain | Notes |
|---------|-------|-------|
| Browser | `authenticateJWT` → `requireMembership` → `[requireRole(PARENT)]` | full CRUD |
| Agent | `authenticateAgent` → `requireScope` | **no DELETE**; scope-gated; `meal:write` for all v0.4.0 writes |
| Display | `authenticateApiKey` | **read-only**, 6-field projection |
- Each write feature: test that agent surface enforces `meal:write` (401/403 without scope).
- Test that display api-key can read but never write.
- Cross-family isolation on all three (never read/write another family's meal).

### INV-4 · CSV round-trip integrity
For every **persisted user-facing Meal scalar** (§1b), these four move in **lockstep**:
`MEALS_CSV_HEADER` ↔ parser aliases ↔ import Zod ↔ export serialize (`csv.ts`).
- Round-trip test: export → re-import → **identical** scalars (incl. nulls as empty cells, not `0`/`""`).
- v0.4.0 CSV-portable adds: **favorite, rating** (#98), **imageUrl** (#103). (Core 5 already wired via #97.)
- v0.4.0 CSV-**excluded** (child relations, document the exclusion): **instructions** (#100), **tags/categories** (#107) unless flattened.
- Malformed cell (bad rating, bad boolean, bad URL) → row rejected with a clear per-row error, not a silent drop.

### INV-5 · SSRF / URL guard
`sourceUrl` (#97, merged) and `imageUrl` (#103) must share **one** URL-safety guard:
- Reject: non-`http(s)` schemes, `localhost`/`127.0.0.0/8`, private + link-local ranges (RFC1918, `169.254/16`, `::1`, `fc00::/7`), credentialed URLs (`user:pass@`).
- One guard util → tested once → both call sites assert they invoke it (REST + agent Zod).
- Placeholder + null handling: empty URL allowed (→ `null`), no fetch performed at validation time.
