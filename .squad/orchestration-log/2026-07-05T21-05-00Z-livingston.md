## What was delivered

### Feature (#180) — MCP/agent binary image upload

- New **`meal:image` scope** added to `AGENT_SCOPES` (additive, distinct from `meal:write`).
- Agent route extended: accepts base64-encoded bytes + declared `contentType`; decodes,
  validates with magic-byte sniffing (`sniffImageMime`) and decoded-size check, then
  persists via the existing `imageStorage` pipeline from #104.
- MCP `apiClient.ts` — new `uploadMealImage(familyId, mealId, base64, contentType)`.
- MCP `tools.ts` — new `upload_meal_image` tool registered with `TOOL_SCOPES.upload_meal_image = "meal:image"`.
- Shared constants updated (`packages/shared/src/constants/index.ts`).
- `FamilySettingsPage.tsx` (web) — scope checkbox added for `meal:image` so agent credentials
  can be granted the new scope from the UI.
- Tests added across api / mcp.

### Diagnostic fix (folded into PR #183 — addresses prod-500 root-cause masking)

Added `console.error(...)` to three previously-silent catch blocks in
`packages/api/src/routes/images.ts`:
- `[images] upload failed` — upload catch
- `[images] fetch failed` — image-serve catch
- `[images] delete failed` — delete catch

These catch blocks were swallowing errors and returning generic 500s with no server-side
trace, which is why the prod incident (#181) was initially opaque.
